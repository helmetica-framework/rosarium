ClaimDefinition

chrysopoeia.helmetica.io/v1, namespaced

ClaimDefinition is the Schema for the bundlesources API.

Spec

Path Type Default Description

spec.crdNames

object

CRDNames is the .spec.names field of the generated [apiextv1.CustomResourceDefinition]. If not set takes the name from the chart’s metadata or falls back to the default Instance kind. Please note that changing this field generates a new CRD and does not update the existing one. The old CRD will be left in the cluster and must be removed manually.

spec.crdNames.categories

[]string

categories is a list of grouped resources this custom resource belongs to (e.g. 'all'). This is published in API discovery documents, and used by clients to support invocations like kubectl get all.

spec.crdNames.kind (required)

string

kind is the serialized kind of the resource. It is normally CamelCase and singular. Custom resource instances will use this value as the kind attribute in API calls.

spec.crdNames.listKind

string

listKind is the serialized kind of the list for this resource. Defaults to "`kind`List".

spec.crdNames.plural (required)

string

plural is the plural name of the resource to serve. The custom resources are served under /apis/<group>/<version>/…​/<plural>. Must match the name of the CustomResourceDefinition (in the form <names.plural>.<group>). Must be all lowercase.

spec.crdNames.shortNames

[]string

shortNames are short names for the resource, exposed in API discovery documents, and used by clients to support invocations like kubectl get <shortname>. It must be all lowercase.

spec.crdNames.singular

string

singular is the singular name of the resource. It must be all lowercase. Defaults to lowercased kind.

spec.instancePermissions

object

InstancePermissions defines what permissions are required to deploy the Helm chart. The default permissions is equal to binding the "admin" aggregate role in the namespace.

spec.instancePermissions.additionalClusterRules

[]object

AdditionalClusterRules holds additional cluster scoped rules that should be granted on top of the default permissions.

spec.instancePermissions.additionalClusterRules[].apiGroups

[]string

apiGroups is the name of the APIGroup that contains the resources. If multiple API groups are specified, any action requested against one of the enumerated resources in any API group will be allowed. "" represents the core API group and "*" represents all API groups.

spec.instancePermissions.additionalClusterRules[].nonResourceURLs

spec.manages

[]object

Manages declares that this source deploys the operator managing the CRDs of a DependencyGroup. The instance of a managing source is the provider consumers are wired to: it is harnessed to the group’s scope and granted access to the namespaces that require the group. A single group can be managed: the harness proxy scopes a cluster-scoped list to one label, and a label selector cannot express "carries either label".
Validation: max items 1

spec.manages[].dependencyGroup

object

DependencyGroup references a DependencyGroup.

spec.manages[].dependencyGroup.as

string

As overrides the name the scope label is built from, so that a second deployment of the same operator can serve a separate set of consumers. Both the managing operator and its consumers have to set the same alias to end up in the same scope.

spec.manages[].dependencyGroup.name (required)

string

Name of the DependencyGroup.
Validation: min length 1

spec.provides

[]object

Provides lists the DependencyGroups whose CRDs the chart of this source ships. It grants the chart write access to those CRDs and lets Helm install them; it says nothing about who operates them, that is Manages. Exactly one source may provide a group, otherwise two charts install the same CRDs over each other. An operator that bundles its CRDs provides and manages the group, while an operator whose CRDs come in a chart of their own only manages it.
Validation: as must not be set on provides, the CRDs of a group are the same for every consumer

spec.provides[].dependencyGroup

OperatorHarness

chrysopoeia.helmetica.io/v1, cluster

OperatorHarness is the Schema for the operatorharnesses API. It harnesses an operator that would otherwise require cluster-wide permissions by scoping its access to resources carrying the label in .spec.scopeToLabel.

Spec

Path Type Default Description

spec.operator (required)

object

Operator describes the harnessed operator’s workload.

spec.operator.injectProxyConfiguration

boolean

InjectProxyConfiguration defines if the harnessed operator should have the harness proxy injected. If enabled, the harness copies the proxy’s CA certificate to Namespace and registers a mutating webhook that points the operator’s pods at the harness proxy instead of the Kubernetes API server.

spec.operator.namespace (required)

string

Namespace is the namespace the harnessed operator runs in.
Validation: min length 1

spec.operator.serviceAccounts

[]string

ServiceAccounts are the service accounts, in Namespace, the harnessed operator’s pods run as. Only pods running as one of these service accounts are harnessed. If empty, every pod in Namespace is harnessed, which is what a namespace holding a single operator wants: the service account is named by the operator’s chart and does not have to be known up front.

spec.scopeToLabel (required)

string

ScopeToLabel is the label that needs to be present on a resource for the harnessed operator to manage it. It is used to scope cluster-wide permissions: if the harnessed operator does a cluster-scoped list or watch through the harness proxy, it only sees resources carrying this label.
Validation: min length 1
